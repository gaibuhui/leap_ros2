# 参数调参索引（全项目）

> **这份文档解决一个问题**：想调某个东西，它在哪个文件的第几行、改完要不要重编译/重启/重烧。
>
> 标记说明：**【看】** 影响你看到的画面/显示　**【动】** 影响机器人的实际运动/传感器　**【连】** 影响通信链路
>
> 路径速记：
> - 上位机 ROS 工作空间 → `~/leap_ros_ws/src/`
> - 主控板固件 → `/home/lixin/leap_firmware/leap_low_v1/`
> - 图传板固件 → `/media/lixin/新加卷/robot/1.源码/leap_cam/`
> - 一键脚本 → `/media/lixin/新加卷/robot/setup/`

## 0. 总览：改哪里 → 改完要做什么

| 层级 | 典型文件 | 改完要做什么 | 难度 |
|---|---|---|---|
| **一键脚本开关** | `setup/05_run_robot.sh` 顶部变量 | 重新执行脚本即可 | ★ |
| **节点参数（YAML）** | `*_camera/config/*.yaml`、`xuegecar_navigation2/param/*.yaml` | **重启对应节点/launch**（该工作空间是 `--symlink-install`，一般不用重编） | ★ |
| **launch 参数** | `ros2 launch ... map:=xxx url:=xxx params_file:=xxx` | 命令上加参数，立刻生效 | ★ |
| **Qt 界面内控件** | 速度上限两个输入框 | 界面里直接改，**立刻** | ★ |
| **RViz 配置** | `*.rviz` | 界面里改 + `Ctrl+S` 存回文件 | ★ |
| **gmapping 参数** | ⚠️ `slam_gmapping/src/slam_gmapping.cpp` | **改源码 → `colcon build` → 重启**（改 YAML 完全无效） | ★★★ |
| **URDF 几何** | `xuegecar_description/urdf/xuegecar.urdf` | 重启 `robot_state_publisher`（symlink 一般不用重编） | ★★ |
| **固件·运行时可改** | HTTP `POST /api/runtime-config` | 立刻生效，**落 NVS 掉电不丢**，但机器人会重启 | ★ |
| **固件·MAVLink 参数** | MAVLink `PARAM_SET` | 立刻生效，**内存态，重启丢失**，且**仅 mavlink_udp 模式可用** | ★★ |
| **固件·硬编码常量** | `main/control/motion_controller.cpp` 等 | **改源码 → 重烧固件** | ★★★★ |
| **图传板相机** | `leap_cam/main/camera_init.c` | **改源码 → 重烧图传板** | ★★★★ |

### 1.1 `setup/05_run_robot.sh`（主启动脚本）

| 参数 | 行号 | 默认 | 作用 |
|---|---|---|---|
| `WS_DIR` | 36 | `~/leap_ros_ws` | 工作空间路径 |
| `AGENT_VERBOSE` | 54 | `4` | micro-ROS Agent 日志级别。**`6` 会 30 秒刷 32MB 日志**，仅排障用 |
| `AGENT_LOG` | 55 | `/tmp/leap_ros_agent.log` | Agent 日志落盘位置 |
| `AGENT_PORT` | 56 | `8888` | Agent UDP 端口（**须与固件里的一致**，见 §10） |

| `ROBOT_CACHE` | 57 | `/tmp/leap_robot_ip` | 上次发现的机器人 IP 缓存，避免每次扫全网段 |

**用法**：`AGENT_VERBOSE=4 AGENT_PORT=8888 bash 05_run_robot.sh core`

**模式**（`case` 分支集中在脚本第 271 行起）：

| 模式 | 作用 |
|---|---|
| `core` | micro-ROS Agent + robot_state_publisher + TF（**核心链路，终端 A 常驻**） |
| `ekf` / `fusion` | **核心链路 + IMU 融合 EKF**（自动起 IMU 协方差修正、并关掉底盘那条 TF；见 §8） |
| `bringup` | 官方整机 bringup（含 socat + YDLIDAR，需 root 的会绕开） |
| `slam` / `gmapping` | gmapping 建图 |
| `slam-toolbox` | slam_toolbox 建图 |
| `nav` / `navigation` | Nav2 导航（无 RViz） |
| `nav-rviz` | Nav2 导航 + RViz |
| `cam` / `camera` | 视频流节点（**自动向机器人问相机地址**） |
| `lidar` | 单独跑雷达 |
| `agent` | 只跑 Agent（前台） |
| `rviz` | RViz（**默认加载项目自带配置**，可传自定义 `.rviz`） |
| `topics` | 会话状态 + 话题列表 + 定位栈报告 |
| `reset` | 一键复位机器人 + 同步 Agent IP |
| `qtgui` | 启动 Qt 控制面板 |

**通用开关**：`--force` / `-f`（放任意位置）—— 清理占用端口的孤儿 Agent；在 `slam`/`nav` 模式下变成「跳过定位栈互斥检查」。

> ⚠️ `slam`/`slam-toolbox`/`nav`/`nav-rviz` 四个模式**启动前会检查定位栈互斥**（SLAM 与 Nav2 不能同时跑）。理由见 §5 和 README Q27。

### 2.3 相机画面相关链路（想改画面，按这条链找）
```
图传板 192.168.1.102:81   ← 分辨率/画质在【图传板固件】§12，需重烧
   ↓ HTTP MJPEG（首帧要等 8~10 秒！）
xuegecar_camera 节点       ← url/fps/jpeg_quality 在 §2.1
   ↓ /camera/image_raw/compressed
Qt 面板 CameraView         ← 画布固定 640×480（camera_view.cpp:12-13）
RViz（若 Add Image 显示）   ← 话题填 /camera/image_raw/compressed
```
> ⚠️ **首帧延迟**：MJPEG 流是「抓到第一帧才发 HTTP 头」，所以 `curl --max-time 8` 会得到 0 字节。判据见 README Q26。
>
> ⚠️ **「浏览器能看、Qt 却是空白」= 上面这条链断在第 3 环。**
> 浏览器走的是**另一条路**（直连图传板 MJPEG，**完全不经过 ROS**），
> 它能看**不代表** Qt 能看 —— Qt 依赖 `xuegecar_camera` 那个节点正在运行。
> Qt 面板现在**默认在启动 1.5 秒后自动拉起它**（面板底部有开关「启动面板时自动打开摄像头」），
> 也可手动 `bash 05_run_robot.sh cam`。详见 README **Q28**、§3.4。

| 参数 | 现值 | 说明 |
|---|---|---|
| `frequency` | `30.0` | 输出频率 |
| `two_d_mode` | **`true`** | 平面运动，忽略 z/roll/pitch（原为 `false`） |
| `sensor_timeout` | `0.2` | 多久没数据就暂不融合该传感器 |
| `publish_tf` | `true` | 由 EKF 广播 `odom→base_footprint` |
| `map_frame`/`odom_frame`/`base_link_frame`/`world_frame` | `map`/`odom`/**`base_footprint`**/`odom` | ⚠ **`base_link_frame` 必须是 `base_footprint`**，写成 `base_link` 会和 URDF 的 `base_footprint→base_link` 抢 TF、整棵树炸 |
| `odom0` | `/odom` | 轮式里程计 |
| `odom0_config` | 只开 **`vx`** | 不用 x/y：固件那份位置是用**有误差的 yaw** 积分出来的，已被污染；不用 vyaw：轮速差分正是漂移源 |
| `imu0` | **`/imu/data`** | ⚠ **不是 `/imu`**，原因见下 |
| `imu0_config` | 只开 **`vyaw`** | 陀螺角速度（直接测量），远好于轮速差分 |
| `imu0_relative` | `true` | 以第一帧为基准 |

**⚠ 最关键的一处：`imu0` 为什么不是 `/imu`**

固件把 IMU 三个协方差数组的第 0 位都写成了 `-1.0`：

```c
// leap_firmware/leap_low_v1/main/tasks/network/microros_task.cpp
s_imu_msg.orientation_covariance[0]         = -1.0;
s_imu_msg.angular_velocity_covariance[0]    = -1.0;
s_imu_msg.linear_acceleration_covariance[0] = -1.0;
```

在 `sensor_msgs/Imu` 的约定里 `covariance[0] == -1` 表示**该字段无效**，
robot_localization 会**直接丢弃**这些测量值。现象极具迷惑性：
**EKF 起来了、参数也写了 `/imu`、一条报错都没有，但 IMU 完全没参与融合。**

新包 `xuegecar_imu` 里的 `imu_covariance_fixer` 订阅 `/imu` → 补齐协方差 →
转发到 `/imu/data`，**纯上位机方案，不用重烧固件**。
（哪天固件把协方差修好了，把 `imu0` 直接改成 `/imu` 即可，其余不动。）

**配套改动（缺一不可）**

| 改动 | 位置 | 为什么 |
|---|---|---|
| 新增 `publish_tf` 参数（默认 `true`） | `xuegecar_bringup/src/xuegecar_bringup.cpp` + `launch/xuegecar_bringup.launch.py` | EKF 模式下传 `false`，把 `odom→base_footprint` 让给 EKF 独占。否则底盘 **1000 Hz** 盖过 EKF **30 Hz**，位姿在两组值之间来回跳 |
| 新增 `imu_covariance_fixer` 节点 | `~/leap_ros_ws/src/xuegecar_imu/`（新包） | 补协方差（见上） |
| 新增 `ekf_localization.launch.py` | `xuegecar_navigation2/launch/` | 一条命令起「IMU 修正 + EKF」，并自动对齐 IMU 话题 |
| 新增 `ekf` / `fusion` 模式 | `05_run_robot.sh` | 自动完成上述所有事（含 `publish_tf:=false`） |

**验证：**

```bash
ros2 topic hz /odometry/filtered                        # 应约 30 Hz
ros2 topic echo /imu/data --once | grep -A4 covariance  # 应不再是 -1
ros2 topic info /tf -v | grep "Node name"               # odom→base_footprint 只应来自 ekf_filter_node
ros2 run tf2_ros tf2_echo odom base_footprint           # 车静止时应在 0 附近
```

**行为变化（正常，不用慌）**：EKF 以「启动那一刻」为 odom 零点，
所以**启动 EKF 后里程计会归零**。这是里程计的正常行为，
gmapping / Nav2 用 `map→odom` 吸收这个偏移，不受影响；
但**事先标定好的绝对坐标导航点**需要重新对照一次。

**想回退**：不用 `ekf`、照旧用 `core` 即可 —— 所有改动**向后兼容**，
不改参数时的行为与改动前完全一致。

## 14. 四个必须记住的坑（附带影响）

**① gmapping 是「死配置」包**
改 YAML 白费时间，必须改源码重编。这是最容易浪费几小时的一条。

**② Qt 面板的「启动」按钮曾全部失效**（**已修复**）
原来前缀里 source 的是作者家目录 `/home/xuegeros/*` —— **你机器上不存在**，
于是本机工作空间从没被 source 过，四个按钮一律报 `Package 'xuegecar_*' not found`。
现已改为**自动探测** `$XUEGECAR_WS` / `$HOME/leap_ros_ws` 等并重编译（§3.4）。
> 但「**SLAM+Nav2**」那个按钮**仍然别点** —— 它会同时起 gmapping 和 Nav2 两套定位栈，
> 必然触发 TF 冲突、地图剧烈抖动。规则见 §5 / README Q27。

**③ 固件轮距 150 mm ≠ URDF 轮距 200 mm**
固件用它算 yaw 角速度，两者差 33% → 系统性转角误差。
叠加「偏航纯靠轮速差积分」（§11.3），共同构成地图抖动的固件层根因。
> ✅ 已用 EKF 绕开（§8）：`bash 05_run_robot.sh ekf` —— 融合轮子 `vx` + 陀螺 `vyaw`，
> **不再依赖轮速差分的偏航**。但轮距本身仍建议标定（它会影响 `vx` 的尺度）。

**④ 固件 IMU 的协方差写成了 `-1`（= 「该字段无效」）**
`sensor_msgs/Imu` 的约定里 `covariance[0] == -1` 表示该字段不可用，
robot_localization 会**直接丢弃** —— 表现为「EKF 起来了、不报错、但 IMU 完全没融合」。
> 上位机已用 `imu_covariance_fixer` 补齐协方差后转发 `/imu/data`（§8），**不用重烧固件**。
